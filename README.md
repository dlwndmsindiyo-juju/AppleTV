# 🍎 Apple TV OTT Renewal

> 콘텐츠를 발견하는 순간부터 시청과 재방문까지, 더 직관적인 Apple TV 경험을 설계합니다.

Apple TV의 시네마틱한 브랜드 경험과 미니멀한 디자인을 유지하면서 콘텐츠 탐색, 서비스 이해, 시청 흐름을 개선한 팀 프로젝트입니다.

**[배포 사이트 보기](https://apple-tv-redesign.vercel.app/)**

학습·포트폴리오 목적의 비공식 리디자인입니다. 실제 Apple 서비스와 연결된 구독·결제·본편 스트리밍 서비스가 아닙니다.

### 구현 범위와 데모 구분

- 영상은 YouTube IFrame API 기반 재생 경험을 구현했습니다. Apple 본편 제공·DRM 스트리밍 구현을 의미하지 않습니다.
- 구독은 플랜 선택과 상태 저장을 시연하며 PG 결제·서버 결제 검증은 포함되지 않습니다.
- 추가 확인 코드 화면은 현재 데모 모드입니다. 실제 이메일 코드 인증·MFA로 설명하지 않습니다.
- TV+ Assistant의 확인된 구현은 선택형 조건 기반 추천입니다. 자연어 대화·FAQ 연결은 기획 확장 방향입니다.
- 국가별 이용 정보는 TMDB 제공사 데이터를 참고합니다. 실제 Apple 서비스 이용 권한을 보장하지 않습니다.
- 스포츠 화면에는 API 연동과 목업 데이터가 함께 있습니다. 전체 정보의 실시간성을 보장하지 않습니다.
- `/tv`는 웹 기반 TV UI 미리보기이며 스마트 TV 네이티브 앱이 아닙니다.

## 사용자 흐름

**기획한 신규 사용자 여정**

랜딩 → 콘텐츠 탐색 → 작품 상세 → 구독 플랜 → 결제 수단·정보 UI → 구독 확인 → 완료 → 홈

**구현된 주요 흐름**

- 이메일·Google 로그인 → 프로필 선택 → 로그인 홈
- 검색 → 영화·시리즈·인물 결과 → 관련 화면 이동
- 작품 담기 → 그룹 선택 → Firestore 저장 → 다른 화면에서 동일 상태 표시
- 영상 재생 → 진행 기록 저장 → 이어보기 목록 → 같은 영상 위치 복원
- 추천 팝업 → 장르·분위기·시간 선택 → 조건에 맞는 결과 → 필요 시 조건 확장

현재 배포 화면의 비로그인 검색 결과 선택에서는 상세 진입 전에 구독 안내가 표시됩니다. 기획한 상세 탐색 후 구독 흐름에 맞추는 것은 개선 과제입니다.

## 구현에서 집중한 부분

### 최신 검색만 반영

영화·시리즈·인물 요청을 병렬 처리하고 요청 토큰을 비교해 오래된 검색 응답이 최신 결과를 덮지 않도록 했습니다. 제공사 정보는 동시 요청 수를 제한하고 메모리에 캐시합니다.

### 사용자별 상태와 화면 반응성

계정·프로필 변경 시 실시간 구독과 화면 데이터를 교체합니다. 위시리스트는 사용자 조작을 먼저 화면에 반영한 뒤 저장하며, 실패하면 이전 값으로 복구합니다. 비동기 저장 중 프로필 전환에 대한 컨텍스트 고정은 추가 개선 대상입니다.

### 재방문 흐름

영상 ID와 진행률을 저장해 같은 영상의 재생 위치를 복원합니다. 페이지 뒤로 이동 시 스크롤과 포커스를 복원하도록 구성했습니다.

### 설명 가능한 추천

추천 규칙을 순수 함수로 분리했습니다. 선택한 조건을 기본적으로 유지하고 결과가 부족하면 사용자 선택으로 조건을 확장하며, 결과에 추천 이유를 제공합니다.

## 실행 환경 안내

제공된 ZIP은 src만 포함하므로 단독 실행할 수 없습니다. 전체 저장소에서 package.json·lockfile·엔트리 HTML·public 자산·빌드 설정을 확보한 뒤 해당 저장소의 설치 및 실행 스크립트를 사용해야 합니다. 확인하지 않은 실행 명령은 이 문서에 확정해서 적지 않습니다.

소스가 참조하는 주요 환경변수:

```dotenv
VITE_TMDB_API_KEY=
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGEING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_YOUTUBE_API_KEY=
VITE_FOOTBALL_API_KEY=
VITE_FOOTBALL_BASE=
VITE_SPORTS_API_KEY=
VITE_SPORTSDB_BASE=
VITE_OMDb_API_KEY=
```

`MESSAGEING`과 `OMDb` 표기는 현재 소스의 철자를 따릅니다. 이름을 변경한다면 코드와 설정을 함께 수정해야 합니다. API별 설정은 사용 화면에 따라 필요합니다. `VITE_*` 값은 브라우저에 포함되므로 서버용 비밀키를 넣지 않습니다. Firebase 승인 도메인·Firestore 규칙·필요 인덱스와 외부 API의 허용 도메인도 별도 설정해야 합니다.

## 확인한 검증과 향후 개선

- 2026-11-10 배포 홈·검색 결과와 비로그인 구독 안내를 직접 확인했습니다.
- 추천 엔진의 6개 장르 조건·동일 입력 결정성·빈 장르 거부 총 13개 검사를 통과했습니다.
- 전체 빌드, 로그인 이후 저장 플로우, 서버 규칙, 결제, 모바일·TV 실기기 검증은 이번 검토에서 수행하지 않았습니다.

다음 개선 우선순위는 추천 영역 제목과 데이터 일치, 조회 실패와 이용 불가 상태 구분, 프로필 전환 중 저장 경합, 로컬 데이터 이관 안정성, 프로필별 기록 쿼리, 전역 스타일 분리입니다.
